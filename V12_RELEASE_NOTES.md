# EchoNest v12 — independent characters

## Database deployment (required)

1. Back up Supabase PostgreSQL **before running SQL**.
2. For an existing installation: apply `database/upgrade_existing.sql` (if not already applied), then `database/003_permissions.sql` (if not already applied), then `database/004_v12_independent.sql`.
3. For a fresh installation: apply `database/schema.sql`, `database/003_permissions.sql`, `database/004_v12_independent.sql` in order.
4. Deploy to Render after migrations. Never run two instances of the same bot token simultaneously.
5. Enable Guild Install and User Install in Discord Developer Portal. User-installed commands can remain visible in guilds without the bot; server-side check blocks execution but does not hide the command UI.

## Changes

- Removed invitation, acceptance and ownership transfer commands. Existing share/invite tables are left untouched for safe rollback but no longer consulted.
- Private characters restricted to creator; guild characters restricted to their guild and role access permissions.
- Per-player chat history, long-term summaries, important memories, level, experience, mood, affection.
- Per-user inventory, check-in, exploration, quest; existing guild inventories are consolidated into user inventory by migration.
- Gift UI uses private select and confirmation; quantity is decremented transactionally and character reactions generated by Gemini.
- Explore uses a start button; Gemini writes story and the server independently determines random item reward, including no reward.
- Added /收藏角色 to add/remove personal favorites; /收藏 shows character name, portrait and description.
- Existing image generation and upload, role cards, chat, proactive DMs, Docker and Render configuration retained.
- On creator leaving a guild, characters stay in guild; bot attempts a DM notice showing existing character image, not newly generated artwork.

## Known limitations

- Discord may display user-installed slash commands in guilds without EchoNest, although the bot checks and blocks execution.
- Gift dropdown shows the first 25 available items; users with more than 25 distinct inventory items cannot choose all items in one menu.
- Departure notification reuses the existing portrait, not a newly generated crying image.
- Public/private visibility preference currently applies to `/聊天`; management and inventory UI remains private.
- Chat length cap is 20 characters; long answers can be truncated.
- Existing legacy shared summaries remain in `memories` for rollback, but are not used by v12. New summaries start empty.
- Daily check-in/exploration counters start fresh per-user after migration; old per-guild counters are retained for rollback.
- Proactive messages are limited to DM selected characters and their owner; failed sends can still leave timestamp updated.
